# Ticket: Add `--dry-run` flag to the sync command

**Status:** draft
**Owner (Implementer):** Claude
**Retry count:** 0
**Related project audit:** PROJECT_AUDIT.md
**Baseline:** (set when started; currently 2304ff6)
**Worktree:**

## Problem

`syncer sync <source> <target>` always writes to the target: it creates the
target directory (`src/sync.js` `fs.mkdirSync`) and copies files
(`fs.copyFileSync`). There is no way to see which files a sync would copy
without actually copying them.

## Approach

1. In `src/sync.js`, give `sync` an optional fourth parameter
   `{ dryRun = false } = {}`. When `dryRun` is true, do not call
   `fs.mkdirSync` or `fs.copyFileSync`. Each file is selected exactly as it
   is today (missing in the target, or the target's mtime is older), logs
   `would copy <name>` in place of `copied <name>`, and is still pushed to
   the returned array. If the target does not exist, every regular file in
   the source counts as "would copy" (this already happens, because
   `existsSync(to)` is false).
2. In `bin/sync.js`, accept `--dry-run` anywhere after `sync` (for example
   `syncer sync --dry-run src dst` or `syncer sync src dst --dry-run`): strip
   it from the positional args and pass `{ dryRun: true }`. The summary line
   becomes `N file(s) would be copied` in dry-run mode. The usage message
   becomes `usage: syncer sync [--dry-run] <source> <target>`. Exit code
   stays 0 on success.
3. Add tests to `test/sync.test.js` for dry-run behavior (AC-1 to AC-3).

## Acceptance criteria

- [ ] AC-1: `sync(src, dst, log, { dryRun: true })` returns the same names a real sync would, and leaves `dst` byte-for-byte unchanged (no new files, existing files not overwritten). (test)
- [ ] AC-2: With `dryRun: true` and a `dst` path that does not exist, `dst` is still absent afterwards and every regular source file is returned. (test)
- [ ] AC-3: A file whose target copy is at least as new as the source is not listed in dry-run mode, the same as a real sync. (test)
- [ ] AC-4: `node bin/sync.js sync --dry-run <src> <dst>` prints `would copy <name>` for each file plus `N file(s) would be copied`, exits 0, and writes nothing to `<dst>`. The flag also works after the positional args. (command)
- [ ] AC-5: `node bin/sync.js sync <src> <dst>` without the flag behaves exactly as before (`copied <name>`, `N file(s) copied`). Bad usage still exits 1 and shows the updated usage line. (command)
- [ ] AC-6: `node --test` passes. (`docket verify`)

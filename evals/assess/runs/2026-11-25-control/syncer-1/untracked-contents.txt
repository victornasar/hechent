# Ticket: Add `--dry-run` flag to the sync command

**Status:** draft
**Owner (Implementer):**
**Retry count:** 0
**Related project audit:** PROJECT_AUDIT.md
**Baseline:** (set when started)
**Worktree:**

## Problem

`syncer sync <source> <target>` always writes to the target. There's no way
to see which files a sync would copy without actually copying them, so you
can't check a sync before running it on a real target.

## Approach

1. In `src/sync.js`, extend `sync(source, target, log = console.log)` with a
   fourth parameter `options = {}` that accepts `{ dryRun: boolean }`. The
   existing three-argument calls keep working unchanged.
2. When `dryRun` is true, `sync`:
   - skips `fs.mkdirSync(target, …)`. A target that doesn't exist counts as
     empty, so every regular file in source would be copied.
   - skips `fs.copyFileSync`.
   - still picks files with the existing missing-or-older mtime rule, logs
     `would copy <name>` instead of `copied <name>`, and returns the list of
     names it would copy.
3. In `bin/sync.js`, accept `--dry-run` anywhere in the arguments. Remove it
   before reading `<source>` and `<target>` from the positional arguments,
   and pass `{ dryRun: true }` to `sync`. The summary line becomes
   `N file(s) would be copied (dry run)` in dry-run mode, and stays
   `N file(s) copied` otherwise. The usage string becomes
   `usage: syncer sync [--dry-run] <source> <target>`.
4. Add tests in `test/sync.test.js` covering the ACs below.

## Acceptance criteria

- [ ] AC-1: `sync(src, dst, log, { dryRun: true })` returns the names that
      a real sync would copy (missing or older in target), and leaves the
      target directory's contents and mtimes unchanged (`node --test`).
- [ ] AC-2: With `dryRun: true` and a target path that does not exist, the
      target is not created, and the return value lists every regular file
      in source (`node --test`).
- [ ] AC-3: With `dryRun: true`, the log callback receives `would copy <name>`
      for each candidate, and never `copied <name>` (`node --test`).
- [ ] AC-4: `sync(src, dst, log)` with no options behaves exactly as before:
      the existing test `copies files missing from the target` still passes.
- [ ] AC-5: The CLI `node bin/sync.js sync --dry-run <src> <dst>` exits 0,
      prints `N file(s) would be copied (dry run)`, and leaves `<dst>`
      unchanged. Running it without the flag still prints `N file(s) copied`
      (`node --test`, spawning the CLI with `child_process`).

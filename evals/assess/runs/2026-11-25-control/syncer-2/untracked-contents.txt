# Ticket: Add `--dry-run` flag to the sync command

**Status:** draft
**Owner (Implementer):**
**Retry count:** 0
**Related project audit:** PROJECT_AUDIT.md
**Baseline:** (set when started)
**Worktree:**

## Problem

`syncer sync <source> <target>` writes to the target right away: it creates
the target directory and copies files. There is no way to see which files a
sync would copy without actually copying them.

## Approach

1. In `src/sync.js`, give `sync(source, target, log, options)` a fourth
   parameter `options = {}` that accepts `{ dryRun: boolean }`. When
   `dryRun` is true:
   - do not call `fs.mkdirSync` on the target, and do not call
     `fs.copyFileSync`;
   - work out the same set of files as a real sync: a file is picked when
     the target is missing (or the target directory doesn't exist yet), or
     when the target file's mtime is older than the source's;
   - log `would copy <name>` instead of `copied <name>`;
   - return the list of names that would be copied.
   Leave the existing call shape `sync(source, target, log)` working as it
   does now.
2. In `bin/sync.js`, accept `--dry-run` anywhere after `sync` (pull it out
   of argv before reading the positional `source`/`target`). Pass
   `{ dryRun: true }` to `sync`. Print the summary as
   `N file(s) would be copied` in dry-run mode, and keep
   `N file(s) copied` otherwise. Update the usage line to
   `usage: syncer sync [--dry-run] <source> <target>`. Any other argument
   starting with `--` is an error: print the usage line and exit 1.
3. Add tests in `test/sync.test.js` (`node --test`).

## Acceptance criteria

- [ ] AC-1: With `{ dryRun: true }`, `sync` returns the names of files that
      are missing from the target, and copies none of them (the target
      files still don't exist afterwards). (test)
- [ ] AC-2: With `{ dryRun: true }` and a target directory that doesn't
      exist, `sync` returns the source files and does not create the
      target directory. (test)
- [ ] AC-3: With `{ dryRun: true }`, a target file that is newer than the
      source is not in the returned list, and a target file that is older
      is in the list and keeps its old content. (test)
- [ ] AC-4: In dry-run mode the log callback gets `would copy <name>` for
      each file. (test)
- [ ] AC-5: `node bin/sync.js sync --dry-run <src> <dst>` exits 0, prints
      `N file(s) would be copied`, and leaves `<dst>` unchanged. Running it
      without `--dry-run` still copies and prints `N file(s) copied`.
      (test spawning the CLI)
- [ ] AC-6: The existing test `copies files missing from the target` still
      passes, and `node --test` exits 0 (via `docket verify`).
